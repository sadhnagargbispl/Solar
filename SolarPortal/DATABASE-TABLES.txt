========================================================================
IMPORTANT NOTES
========================================================================

1) IncConnections and IncWithdrawals have NO MIGRATION.
   Both are registered as DbSets in ApplicationDbContext.cs (lines 26-27)
   but neither appears in any migration file nor in
   ApplicationDbContextModelSnapshot.cs. They must be created
   out-of-band in the live database (the IncWithdrawal entity comment
   says it "maps to the EXISTING IncWithdrawals table").
   => Running Update-Database on a fresh DB will NOT create them.

2) SOFT DELETE.
   Every entity deriving from BaseEntity has a global query filter
   HasQueryFilter(x => !x.IsDeleted), so rows are never physically
   removed - they are flagged with IsDeleted = 1.
   EXCEPTION: IncWithdrawal is a plain class with no IsDeleted column.

3) AUDIT TIMESTAMPS.
   SaveChangesAsync() automatically sets CreatedAt (on insert) and
   UpdatedAt (on update) for all BaseEntity types, using DateTime.UtcNow.
